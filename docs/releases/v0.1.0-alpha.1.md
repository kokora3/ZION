# ZION v0.1.0-alpha.1 Release Notes

This is the first complete Minimum Decentralized Product alpha for `zion-alpha-1`.

It includes canonical encoding and typed IDs; member identities and key rotation; deterministic state/StateHash; four-validator CometBFT finality; ACTIVE-member governance; libp2p discovery; durable runtime/state sync/transaction relay; a bounded immutable object store; signed off-chain Board; canonical Research/Resource registries; a replaceable local-node Web client; explicit secret-free canonical state export/import; and local structured observability.

Release archives target Windows amd64 and Linux amd64 and contain `zion-node`, `zionctl`, notices, example configurations, operator runbooks, and injected commit/build-date metadata. `SHA256SUMS` authenticates bytes only when the manifest is obtained through a trusted channel. Artifacts are not code-signed.

Final acceptance used four CometBFT validators, one bootstrap node, and two
NORMAL nodes (one outbound-only). It covered quorum loss/recovery, state sync,
Board and object propagation, Research/Resource governance admission,
restart/cache recovery, state export/import, Web E2E, race detection, bounded
fuzzing, and a 60-second resource soak. Exact local validation results and
artifact hashes are recorded in `validation-v0.1.0-alpha.1.md`.

Breaking alpha resets remain possible. State sync is not a light client. Board/object data is public and not guaranteed permanent. The registry never executes content. Relay/DHT/NAT traversal, large-object chunking/replication/GC, wallet/keystore UX, guardian recovery, proof-of-human, economic/reputation layers, hardware attestation, and automated repository execution/update are deferred.
