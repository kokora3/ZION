# ZION Local API v1

The API base path is /v1 and defaults to 127.0.0.1:42001. Non-loopback binding requires an explicit bearer token and emits a startup warning. No wildcard CORS origin is accepted; exact configured development origins are echoed only after matching, including bounded `OPTIONS` preflight responses.

## Endpoints

- GET /v1/health returns liveness and readiness. A process can be live while UNINITIALIZED or SYNCING; readiness requires RUNNING and SYNCED.
- GET /v1/status returns network/genesis, lifecycle, roles, PeerID, sync status, accepted height, StateHash, consensus activity, validator authorization, and protocol version.
- GET /v1/peers returns bounded usable general-P2P peers.
- GET /v1/state returns counts and a state summary, never a full unbounded snapshot.
- GET /v1/identities/{identity_id} and /v1/memberships/{identity_id} return public canonical information.
- GET /v1/governance/proposals and /v1/governance/proposals/{proposal_id} inspect bounded canonical governance state. Lists accept offset and limit up to 100.
- POST /v1/transactions accepts {"encoding":"base64","transaction":"..."} containing one already-signed canonical transaction.
- GET /v1/transactions/{tx_id} returns bounded recent local status.

Submission can be REJECTED_LOCALLY, ACCEPTED_FOR_SUBMISSION, SUBMITTED_TO_CONSENSUS, KNOWN_ALREADY, or FINALIZED. Decode, relay, or CheckTx success is never represented as finality.

Errors use {"code":"STABLE_CODE","message":"bounded explanation"}. Bodies, headers, URIs, pagination, concurrent work, and server read/write/idle time are bounded. Responses contain no private keys or bearer tokens and there are no admin membership, validator, or governance-bypass routes. Remote exposure should be protected by host firewall and TLS termination in addition to the required bearer token.

`zionctl --bearer-token-file <path> ...` reads remote-API credentials from a bounded local file without placing the token in command arguments or output.
