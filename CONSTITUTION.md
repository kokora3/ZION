# ZION Constitution

These architectural invariants are drawn from `SPEC.md` and guide ZION Protocol v0.1:

1. ZION has no mandatory central application server.
2. ZION has no mandatory central application database.
3. ZION has no single protocol superuser.
4. Clients are replaceable.
5. The chain stores compact trusted state, not bulk content.
6. Protocol objects are integrity-verifiable.
7. Public distributed content may not be globally erasable after distribution.
8. Resource usage must remain bounded before data is accepted.
9. Protocol formats are explicitly versioned.
10. Identity keys support rotation and revocation.
11. Consensus state is deterministic.
12. Alpha state is exportable and migratable.
